============================================================
0. CORE BUSINESS RULE
============================================================

The most important rule of the system is:

EVERY CLASS TEACHER IS A TEACHER,
BUT EVERY TEACHER IS NOT A CLASS TEACHER.

A teacher can have:

A) SUBJECT TEACHER role/capability
OR
B) CLASS TEACHER assignment
OR
C) BOTH

The Class Teacher assignment should be dynamic.

Example:

Teacher: Rohan Mehta

Current assignments:
• Mathematics — Grade 9-A
• Science — Grade 10-A
• Class Teacher — Grade 9-A

Therefore:

As Subject Teacher:
→ sees only relevant academic/student information for assigned subjects/classes.

As Class Teacher:
→ receives an additional "My Class" module
→ gets broader visibility into students of Grade 9-A
→ gets class-level operational capabilities
→ gets controlled fee collection capability
→ gets class-level attendance/behavior/academic overview
→ can view payment records relevant to students in his/her class

If the Principal removes the Class Teacher assignment:

→ "My Class" should disappear
→ Class Teacher-only actions should disappear
→ Fee collection capability should disappear
→ Teacher retains normal Subject Teacher capabilities.

DO NOT create separate duplicate user accounts for this.

The system should derive capabilities from:

USER
+
ROLE
+
SUBJECT ASSIGNMENTS
+
CLASS TEACHER ASSIGNMENTS
+
PERMISSIONS

============================================================
3. SUBJECT TEACHER — WHAT SHOULD THEY SEE?
============================================================

A normal Subject Teacher should have LIMITED student visibility.

They should NOT automatically see every financial or administrative detail of a student.

For students belonging to classes/subjects they teach, they may see:

• Student name
• Student photo/avatar
• Roll number
• Class/section
• Admission number
• Basic contact information where appropriate
• Subject-specific attendance
• Subject marks
• Subject assessments
• Subject performance
• Relevant academic history
• Relevant behavior information if permission allows
• Their own subject-related remarks

They should NOT see by default:

• Full fee ledger
• Fee collection controls
• Payment collection
• Payment verification
• Financial transactions
• Family financial information
• Other subjects' confidential academic data
• Principal-only information
• School-wide financial reports

The principle is:

SUBJECT TEACHER =
ACADEMIC VIEW WITH SUBJECT SCOPE

NOT:

SCHOOL-WIDE ADMINISTRATIVE VIEW
